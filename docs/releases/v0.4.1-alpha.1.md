# Mechanism Studio v0.4.1-alpha.1

Mechanism Studio is a project-local authoring skill and reusable runtime for source-aware mechanical studies, exploded views and synchronized visual stories. This public **Alpha** makes the current workflow available for experimentation and feedback. Interfaces and example adapters may change.

## What is included

- An original **80-part planetary reducer**, with stable part identities, a 36-second English Atlas loop, staged disassembly/reassembly, sun–planet mesh detail and shaft-bearing teardown/rolling detail. The ideal 4:1 gear relationship drives the input and output bearings; limitations and geometry assumptions are recorded with the example.
- A shared **executable presentation plan** for display offsets, fixed-envelope orthographic cameras, nearby retained labels and material accents/opacity. The mechanical adapter stays separate. Gearbox, Robotiq and planetary examples demonstrate integration, with a starter template and numerical plan checker.
- The existing modular skill, Atlas white/black-line default and optional cinematic treatment, direct-frame compositor, code-generated music and optional voice interfaces.
- An updated gallery and example catalogue: **11 experiences across 10 models**, led by the planetary study. README and module guides distinguish preview, tests, optional CAD tools and video export.
- A tighter source-release gate, explicit Python setup for CI and a documented clean-install path. Score tests support both independent Git checkouts and extracted source archives, without adopting a parent repository's index. Generated scores, videos, render frames and local caches are excluded from the source release.

## Try the featured study

Use Node.js 20.10+ and a browser with WebGL2. CI targets Node.js 22 and 24.

```sh
npm ci
node examples/planetary-gears/audio/build.mjs
node examples/planetary-gears/serve.mjs
```

Open `http://127.0.0.1:4193/` and click **Play with music**. The included model does not require Blender, a speech key or an external model download. Run `npm run preview` separately for the gallery at `http://127.0.0.1:4179/`.

The full `npm test` suite additionally needs Git, Python 3 and network access on its first run to fetch pinned, hash-verified upstream meshes. FFmpeg/FFprobe are optional for video encoding. Native CAD tests and import tools require their separately documented environment.

## Alpha boundaries

This is an authoring toolkit, not a general automatic CAD disassembly or engineering-validation system. Text/image inputs require explicit assumptions; assembly and joint relationships are not reliably inferred from arbitrary models. The planetary model is original teaching geometry with prescribed ideal kinematics, not manufacturing CAD, loaded contact analysis or a collision-free service procedure.

The direct-frame browser adapter and MP4 encoder are available, but a single-command browser-to-video renderer is not yet included. Source checks, numerical mechanics checks and sampled media review are separate evidence. An earlier local planetary film is documented with its review limitations; generated MP4s are not included as release assets.

The Allegro and Robotiq media delivery records retain their historical input hashes. Their strict delivery checks report current runtime drift: the old pixel comparison does not certify the updated shell or migrated Robotiq adapter. Numerical regression tests cover the current source, but no new full film export or continuous audiovisual acceptance review is claimed for those two studies in this release. The planetary delivery record's version-only metadata drift is documented separately.

Original code, skill documentation and the planetary model/score use MIT. Third-party models, sounds and derived assets retain their own notices and licenses. See [licensing](../licensing.md) and [third-party notices](../../THIRD_PARTY_NOTICES.md).
