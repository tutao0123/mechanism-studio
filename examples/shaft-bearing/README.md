# Galileo 2: source-aware STEP assembly inspection

This example imports the real [Galileo 2 Extruder](https://github.com/JaredC01/Galileo2), designed by JaredC01 and the Galileo 2 contributors. It is a compact planetary geared filament extruder with a carrier shaft, bearing supports and repeated M3 screws. The retained STEP also contains an X carriage and a dummy toolhead PCB. It is the complete upstream assembly, rather than a newly constructed shaft fixture.

Open the local inspection page at [localhost:4179/examples/shaft-bearing/](http://127.0.0.1:4179/examples/shaft-bearing/).

## What to inspect

The page uses the shared Mechanism Studio viewer and assembly observation state. English controls, white surfaces and fine dark feature lines follow the project's mechanical atlas style.

- Pick a surface in the model to select its source occurrence and reveal its row in the assembly tree. Selecting a tree row highlights that occurrence; selecting an assembly includes its descendant geometry.
- Search the tree by label or identity. Expand assemblies to follow the actual parent structure.
- Select an M3 screw and use **Other instances** to visit its copies. They share one source definition and display mesh, but each has a different occurrence identity and placement.
- Hide a part or subtree, isolate a selection, use **Show context**, and restore the view with **Restore all**. These are display operations; source identities and matrices remain unchanged.
- Switch between isometric, front, side and top views. **Explode** applies observation offsets; it is not a collision-checked removal sequence.
- Inspect **Source placement matrices** for the selected occurrence's local and accumulated world placements in source coordinates and millimetres.

Useful source parts are `Carrier` (the planetary carrier shaft), `front_bearing_holder`, and the MR148 bearings. The [official assembly manual](https://github.com/JaredC01/Galileo2/blob/98f8a37944d7277cd37231776400553cc402219f/manuals/Galileo_2_Extruder_Assembly_Manual.pdf) identifies the carrier shaft and explains that the front bearing holder supports it with an MR148 bearing and two M3x8 screws. `main_gear_g2` is the separate drive gear mounted on the carrier shaft. These functional labels come from the upstream design and manual, rather than from shape recognition.

## Identity and hierarchy

| Source structure | Count |
| --- | ---: |
| Product definitions | 69 |
| Occurrences, including the root | 147 |
| Part occurrences | 126 |
| Assembly occurrences, including the root | 21 |
| STEP `NEXT_ASSEMBLY_USAGE_OCCURRENCE` relations | 146 |

OCCT's `STEPCAFControl_Reader.FindInstance` maps each real STEP usage relation to its XCAF component and referred product definition. Display names are labels, not identity keys. IDs contain the source hash, source entity references and occurrence path. They remain stable when this exact source is remeshed with the pinned importer; another STEP export may renumber entities and receive different IDs.

The source contains one assembly that also owns a body: `front_body_ECAS_coupler`. Its housing geometry and its real child components are both retained. Anonymous SOLID labels generated by XCAF are folded into the owning definition's display geometry; they do not become invented engineering parts or STEP usage relations. Consequently, the number of geometry-bearing occurrences can differ from the literal source part count.

In the source `Fasteners` group, shared definitions are placed as follows:

| Definition | Occurrences |
| --- | ---: |
| M3x6 FHCS | 7 |
| M3x8 SHCS | 3 |
| M3x20 SHCS | 5 |
| M3x30 SHCS | 4 |
| M3x50 SHCS | 1 |

Additional fasteners in the carriage retain their own source definitions. Similar names are never used to merge them.

Definition geometry is imported in millimetres in the native STEP axes. The display converts points to metres as `0.001 * [x, z, -y]` and converts every placement using the full basis change `C * M_source * inverse(C)`, including rotations. Display wrappers keep hide, isolate and explode state separate from the retained local and world matrices.

## Rebuild locally

Run from the Mechanism Studio project root, with the Node dependencies installed and an existing `uv` executable available:

```powershell
./tools/cad/setup-xcaf.ps1
npm run import:shaft-bearing
npm run preview
```

The setup creates the pinned CAD runtime in `.tools/cad-python`. Controllable caches, downloaded runtimes, temporary files and import intermediates stay inside this project; no global skill, PATH or tool permission is changed. See the [XCAF backend notes](../../tools/cad/README-xcaf.md) for runtime details and the equivalent setup on other platforms.

The import runs two tessellations and checks that their definition identities, occurrence paths, hierarchy and source matrices agree. The baseline fine settings are 0.08 mm linear deflection and 0.4 radians angular deflection; the coarse settings are 0.3 mm and 0.7 radians. Faces that do not mesh at the initial settings can be retried individually with explicit finer or coarser settings. Recovery attempts and any remaining unmeshed faces are recorded in the generated face data and [import report](assets/import-report.json). These are meshing inputs and diagnostics, not a guaranteed global dimensional error bound or engineering acceptance test.

Generated public assets are:

- [assembly-manifest.json](assets/assembly-manifest.json): reusable definitions, actual source occurrences, parent paths and placements.
- [assembly.glb](assets/assembly.glb): triangulated display geometry with occurrence nodes and shared definition meshes.
- [scene-contract.json](assets/scene-contract.json): display ownership, identity and observation offsets.
- [import-report.json](assets/import-report.json): importer versions, source/display hashes, remeshing comparison and geometry diagnostics.

Intermediate XCAF exports are kept under the ignored `output/cad-research/` directory.

## Verification and limits

```powershell
node --test examples/shaft-bearing/tests/*.test.mjs
npm test
```

The example checks the original source hash, product/usage graph, repeated screw instances, GLB parent structure, local/world transform conversion, display bindings and preservation of source state during observation changes. The import command separately verifies identity across the two tessellation settings. Browser verification should additionally exercise tree-to-model and model-to-tree selection and visibility controls.

This phase provides source-aware assembly inspection. It does not recover native mates, infer joint axes or limits, solve constraints, simulate operation, certify clearances, or calculate a disassembly order. Face indices refer to imported definition topology; they are not persistent native feature IDs. The display is a tessellated derivative, while the unchanged STEP remains the retained engineering source.
